# `investigate` 呼び出し指示

担当者は作業前に `.agents/skills/delegate-investigate/SKILL.md` と `.agents/skills/repository-memory/SKILL.md` を読む。子は委譲元向けの起動・評価を実行せず、自身の役割方針と報告を適用する。
委譲元エージェントは以下の5項目を今回の調査に合わせて記入し、起動時に渡す。担当者が単独で問いを理解できる量のコンテキストを選ぶ。参照できる資料はパスと該当箇所を示し、参照できない情報は必要部分を本文に含める。会話履歴の継承だけに依存しない。情報が足りなければ担当者は不足点を委譲元エージェントに報告する。

```markdown
## 期待するゴール
- 知見報告（本文付き候補・既存対応済み・該当なし）も提出する。
- 解く問いと提出する報告：
## 許可する作業
- メモリーは保存不可。関連既存知見と候補本文は委譲元へ報告する：
- 調査範囲と使用できる読取り・検索：
## 実行してはいけない作業
- 範囲外の操作、ファイル編集、追加委譲、外部書込み：
## 必要なコンテキスト
- 関連既存知見、[repository-memory](../../repository-memory/SKILL.md) の参照、記録可否と明示保存先：
- 背景・症状・再現条件、確認済みの事実、参照資料のパスと該当箇所、制約、実施済み確認と結果：
## 完了条件
- 候補なら完成本文と根拠を報告する。採否・保存先の最終判断は委譲元が行う：
- 条件ごとに、委譲元エージェントが確認する回答・根拠と合否の判定方法：
- 未解決・未確認事項の報告：
```

## 記入例：失敗原因の調査（仮想案件）

```markdown
## 期待するゴール
- 知見報告（本文付き候補・既存対応済み・該当なし）も提出する。
- `uv run pytest tests/test_import.py` で `test_empty_title` が失敗する原因を報告する。
## 許可する作業
- メモリーは保存不可。候補があれば本文と根拠を委譲元へ報告する。
- `tests/test_import.py` と対象の import 処理、その直接参照先を読み、必要なら失敗したテストを再現する。
## 実行してはいけない作業
- ファイル編集、追加委譲、外部サービスへの書込み、根拠のない周辺機能への調査拡大。
## 必要なコンテキスト
- 関連既存知見は未設定。メモリーは保存不可。
- 失敗操作は上記コマンド。`test_empty_title` は空の title に入力エラーを期待するが、観測結果は空の title のレコードが生成される。テスト位置は `tests/test_import.py` の `test_empty_title`。委譲元エージェントはまだ原因を確認していない。既に同コマンドが失敗したため、再現は根拠が必要な場合に限る。
## 完了条件
- 候補があれば完成本文と根拠を報告し、委譲元が採否を判断できる。
- 委譲元エージェントが報告のファイル位置と該当処理を読んで、失敗に至る経路を追える。
- 観測事実と原因仮説を分け、未解決事項と未確認範囲を報告する。原因が確定しなければ断定しない。
```

委譲元エージェントは各条件の根拠を確認して判定する。未解決事項があること自体と、必須条件の未達は区別する。
