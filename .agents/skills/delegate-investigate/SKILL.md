# 調査

委譲元エージェントは、サブエージェントを起動して結果を評価するエージェントを指す。

## 委譲元エージェントによる呼び出しと評価

複数ファイル・複数コマンドにまたがる調査と、インターネット等の外部アクセスを伴う調査では、委譲元エージェントは [呼び出し指示テンプレート](references/agent-instructions.md) と [repository-memory](../repository-memory/SKILL.md) を読み、それに従い5項目を具体化した指示文を作成する。起動手順は現在の実行環境に対応する手順だけを読んで従う（Codex: [launch-codex.md](references/launch-codex.md)、Claude Code: [launch-claude.md](references/launch-claude.md)）。テンプレートの「必要なコンテキスト」には委譲元エージェントのコンテキストの必要な箇所を抜粋し、要約を最小にする。起動手順に従って `investigate` 役割を指定し、原因調査では症状と調査範囲、外部調査では問い・範囲・比較観点を渡す。完了報告を待ち、委譲元エージェントが回答・根拠と完了条件を照合する。必須条件の未達・未確認は完了扱いにせず、対象外の未確認範囲とは区別する。単一ファイルの確認や1〜2回の検索で済む軽微な調査は、委譲元エージェントが直接行ってよい。

完了報告を収集した委譲元エージェントは、サブエージェントの完了報告に不明点・矛盾・根拠の不足などがあり、報告だけでは判断できない場合に、必要に応じて [サブエージェント履歴の参照](../../../.repository-docs/operations/subagent-history.md) に従い、対象サブエージェントの履歴を必要な範囲で確認する。

上記の基準に該当する調査は `investigate` に委譲する。ユーザーが委譲元エージェントによる直接処理を明示した場合、または指定役割で起動できない場合は委譲元エージェントが調査し、起動できなかった場合はその理由を報告する。

## 役割固有の作業方針

エラー時は症状・失敗した操作・再現条件を確認し、直接関連する箇所から調べる。原因を示す根拠があるときだけ隣接範囲へ広げる。通常の探索的調査は目的に応じて広く調べてよい。関連箇所が不明なら `uv run --project <repository-root> --locked --no-sync --offline python -X utf8 <repository-root>/.harness/scripts/inspect_repo.py search <語句>` で候補を探し、`show` で必要な範囲だけ読む。関係する構成だけ [.repository-docs/architecture.md](../../../.repository-docs/architecture.md) で確認する。実行環境がファイル編集の禁止を保証できない場合は、同等に実行できると扱わず、その制約と代替手順を委譲元エージェントに報告する。

計画検討に必要な外部調査では一次資料を優先し、Web検索で見つけた根拠の実ページを開いて確認する。`investigate` はファイルを編集せず、追加の委譲もしない。

## 報告と引継ぎ

観測事実と仮説を区別し、原因と根拠、未解決事項を委譲元エージェントに報告する。外部調査では結論、出典URL、実ページで確認した該当箇所と事実、必要な比較、推論、未確認点を示す。検索ツールが利用できない場合は確認できなかった範囲を明示する。計画の確定と採用判断は委譲元エージェントが行い、修正が必要なら委譲元エージェントが `implement` を起動する。経験した再利用可能な知見は [repository-memory](../repository-memory/SKILL.md) に従い完成本文と根拠を報告する。記録の採否・保存先は委譲元が決める。
