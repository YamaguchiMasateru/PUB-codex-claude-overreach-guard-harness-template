# 検証

委譲元エージェントは、サブエージェントを起動して結果を評価するエージェントを指す。

## 委譲元エージェントによる呼び出しと評価

運用指示・規約（AGENTS.md や Skill を含む）または動作設定（`.conf`、`.toml` など）の変更後は、ユーザーから検証依頼がなくても委譲元エージェントが `verify` を起動する。検証の依頼では規模にかかわらず、委譲元エージェントは [呼び出し指示テンプレート](references/agent-instructions.md) と [repository-memory](../repository-memory/SKILL.md) を読み、それに従い5項目を具体化した指示文を作成する。起動手順は現在の実行環境に対応する手順だけを読んで従う（Codex: [launch-codex.md](references/launch-codex.md)、Claude Code: [launch-claude.md](references/launch-claude.md)）。テンプレートの「必要なコンテキスト」には委譲元エージェントのコンテキストの必要な箇所を抜粋し、要約を最小にする。起動手順に従って `verify` 役割を指定し、確認対象と必要なチェックを渡す。完了報告を待ち、委譲元エージェントが結果・ログと完了条件を照合する。必須条件の未達・未確認は完了扱いにせず、対象外の未確認範囲とは区別する。

完了報告を収集した委譲元エージェントは、サブエージェントの完了報告に不明点・矛盾・根拠の不足などがあり、報告だけでは判断できない場合に、必要に応じて [サブエージェント履歴の参照](../../../.repository-docs/operations/subagent-history.md) に従い、対象サブエージェントの履歴を必要な範囲で確認する。

検証は原則として `verify` に委譲する。ユーザーが委譲元エージェントによる直接処理を明示した場合、または指定役割で起動できない場合は委譲元エージェントが検証し、起動できなかった場合はその理由を報告する。

## 役割固有の作業方針

意図と差分を照合し、直接関係する正本と参照の間の矛盾・重複・古い参照・優先関係の不整合を確認する。設定は対象に応じて構文・必須項目・参照先と直接影響する挙動を最小限確認する。変更による具体的な失敗を検出できる最小の確認を選ぶ。通常はモック・fixture・ローカル単体で検証し、委譲元エージェント・別役割が成功済みの確認を重複実行しない。実行環境が書込み先をGit管理外の検査ログに限る制限を保証できない場合は、同等に実行できると扱わず、その制約と代替手順を委譲元エージェントに報告する。

検証エージェントが書き込むのは Git 管理外の検査ログだけとし、追加の委譲をしない。ユーザーが明示した実サービス接続検証は指定範囲で行い、対象環境が不明なら確認する。外部状態や本番への書き込みは検証指示から推定しない。

## 報告と引継ぎ

失敗時は表示された要約と該当ログから原因範囲を絞り、根拠があるときだけ調査範囲を広げる。確認結果、ログの場所、未実施・失敗・未確認の範囲を区別して報告する。修正を要する失敗は要点とログの場所を委譲元エージェントへ渡し、委譲元エージェントが `implement` に引き継ぐ。実装の修正と必要な再確認は `implement` が担当する。

経験した再利用可能な知見は [repository-memory](../repository-memory/SKILL.md) に従い完成本文と根拠を報告し、Git管理対象へは保存しない。
