# `review` 呼び出し指示

担当者は作業前に `.agents/skills/delegate-review/SKILL.md` と `.agents/skills/repository-memory/SKILL.md` を読む。子は委譲元向けの起動・評価を実行せず、自身の役割方針と報告を適用する。
委譲元エージェントは以下の5項目を今回の差分に合わせて記入し、起動時に渡す。担当者が単独で変更を理解できる量のコンテキストを選ぶ。参照できる資料はパスと該当箇所を示し、参照できない情報は必要部分を本文に含める。会話履歴の継承だけに依存しない。情報が足りなければ担当者は不足点を委譲元エージェントに報告する。

```markdown
## 期待するゴール
- 知見報告（本文付き候補・既存対応済み・該当なし）も提出する。
- レビュー対象と報告する成果：
## 許可する作業
- メモリーは保存不可。関連既存知見と候補本文は委譲元へ報告する：
- 対象差分・関連資料の読取り、必要な局所確認：
- レビュー本体は実行環境の標準レビュー機能で行う。Claude Code では `/code-review`（Skill ツールで `code-review`）、Codex では非対話の `/review` を使う。
## 実行してはいけない作業
- ファイル編集、追加委譲、許可されていない外部書込み：
## 必要なコンテキスト
- 関連既存知見、[repository-memory](../../repository-memory/SKILL.md) の参照、記録可否と明示保存先：
- 変更目的、対象差分、観点、参照資料のパスと該当箇所、制約、実施済み確認と結果：
## 完了条件
- 候補なら完成本文と根拠を報告する。採否・保存先の最終判断は委譲元が行う：
- 条件ごとに、委譲元エージェントが確認する指摘と根拠、または指摘なしの報告と判定方法：
- 未確認範囲の報告：
```

## 記入例：CLI の入力検証差分をレビュー（仮想案件）

```markdown
## 期待するゴール
- 知見報告（本文付き候補・既存対応済み・該当なし）も提出する。
- `--output` の空文字を拒否する変更について、利用者に影響する欠陥を報告する。
## 許可する作業
- メモリーは保存不可。候補があれば本文と根拠を委譲元へ報告する。
- `scripts/example_cli.py` と `tests/test_example_cli.py` の差分、既存エラー処理を読み取る。必要なら局所的な読取り専用確認を行う。
- レビュー本体は実行環境の標準レビュー機能で行う（Claude Code は `/code-review`、Codex は `/review` など対象を1つ指定）。結果は本形式で報告する。
## 実行してはいけない作業
- ファイル編集、追加委譲、外部サービスへの書込み。成功済みテストを重複実行しない。
## 必要なコンテキスト
- 関連既存知見は未設定。メモリーは保存不可。
- 変更目的は空文字を処理前に入力エラーにすること。対象は `scripts/example_cli.py` の `parse_args` と `tests/test_example_cli.py` の `test_empty_output`。既存エラー形式は前者の他の引数検証を参照する。委譲元エージェントが変更対象の実在を確認して渡す。`uv run pytest tests/test_example_cli.py` は実装担当が成功と報告済みで、その結果とログの場所も渡す。
## 完了条件
- 候補があれば完成本文と根拠を報告し、委譲元が採否を判断できる。
- 委譲元エージェントが対象とした差分・観点を報告から照合できる。
- 指摘があればファイル位置、影響、再現条件を示し、委譲元エージェントが差分と照合できる。確認できた指摘がなければその旨を明記する。
- 実施した確認と未確認範囲を分けて報告する。
```

上の対象位置は記入例であり、起動前に今回の実在する対象へ置き換える。委譲元エージェントは報告と差分を照合して判定し、一般的な未確認範囲と必須条件の未達を区別する。
