# レビュー

委譲元エージェントは、サブエージェントを起動して結果を評価するエージェントを指す。

## 委譲元エージェントによる呼び出しと評価

レビューの依頼では規模にかかわらず、委譲元エージェントは [呼び出し指示テンプレート](references/agent-instructions.md) と [repository-memory](../repository-memory/SKILL.md) を読み、それに従い5項目を具体化した指示文を作成する。起動手順は現在の実行環境に対応する手順だけを読んで従う（Codex: [launch-codex.md](references/launch-codex.md)、Claude Code: [launch-claude.md](references/launch-claude.md)）。テンプレートの「必要なコンテキスト」には委譲元エージェントのコンテキストの必要な箇所を抜粋し、要約を最小にする。起動手順に従って `review` 役割を指定し、対象差分と観点を渡す。完了報告を待ち、委譲元エージェントが指摘の根拠または指摘なしの報告と完了条件を照合する。必須条件の未達・未確認は完了扱いにせず、対象外の未確認範囲とは区別する。

完了報告を収集した委譲元エージェントは、サブエージェントの完了報告に不明点・矛盾・根拠の不足などがあり、報告だけでは判断できない場合に、必要に応じて [サブエージェント履歴の参照](../../../.repository-docs/operations/subagent-history.md) に従い、対象サブエージェントの履歴を必要な範囲で確認する。

レビューは原則として `review` に委譲する。ユーザーが委譲元エージェントによる直接処理を明示した場合、または指定役割で起動できない場合は委譲元エージェントがレビューし、起動できなかった場合はその理由を報告する。

## 役割固有の作業方針

差分と直接関連する設計・規約を読み、利用者に影響する実際に起こり得る不具合を探す。エラーの確認では失敗した操作と関連箇所から始め、根拠があるときだけ範囲を広げる。通常の探索的レビューでは目的に応じて広く確認してよい。追加の検証が必要なら、既に成功した確認と重複しない最小の確認を委譲元エージェントに提案する。ファイルを編集せず、追加の委譲もしない。実行環境がファイル編集の禁止を保証できない場合は、同等に実行できると扱わず、その制約と代替手順を委譲元エージェントに報告する。

## 報告と引継ぎ

指摘はファイル位置、影響、再現条件を簡潔に示し、確認できた指摘がなければその旨を報告する。実施した確認と未確認の範囲を分ける。再発する指摘は検査や [.repository-docs/conventions.md](../../../.repository-docs/conventions.md) への反映を委譲元エージェントに提案し、必要なら委譲元エージェントが `implement` または `verify` を起動する。

経験した再利用可能な知見は [repository-memory](../repository-memory/SKILL.md) に従い完成本文と根拠を報告し、Git管理対象へは保存しない。
