# 実装

委譲元エージェントは、サブエージェントを起動して結果を評価するエージェントを指す。

## 委譲元エージェントによる呼び出しと評価

実装の依頼では規模にかかわらず、委譲元エージェントは [呼び出し指示テンプレート](references/agent-instructions.md) と [repository-memory](../repository-memory/SKILL.md) を読み、それに従い5項目を具体化した指示文を作成する。起動手順は現在の実行環境に対応する手順だけを読んで従う（Codex: [launch-codex.md](references/launch-codex.md)、Claude Code: [launch-claude.md](references/launch-claude.md)）。テンプレートの「必要なコンテキスト」には委譲元エージェントのコンテキストの必要な箇所を抜粋し、要約を最小にする。参照先がない会話履歴は、必要な発言を原文のまま含める。起動手順に従って `implement` 役割を指定し、担当範囲を渡す。複数の実装エージェントに同じファイルを同時編集させない。完了報告を待ち、委譲元エージェントが差分・確認結果と完了条件を照合する。必須条件の未達・未確認は完了扱いにせず、対象外の未確認範囲とは区別する。

完了報告を収集した委譲元エージェントは、サブエージェントの完了報告に不明点・矛盾・根拠の不足などがあり、報告だけでは判断できない場合に、必要に応じて [サブエージェント履歴の参照](../../../.repository-docs/operations/subagent-history.md) に従い、対象サブエージェントの履歴を必要な範囲で確認する。

実装は原則として `implement` に委譲する。ユーザーが委譲元エージェントによる直接処理を明示した場合、または指定役割で起動できない場合は委譲元エージェントが実装し、起動できなかった場合はその理由を報告する。

## 役割固有の作業方針

関連する [.repository-docs/index.md](../../../.repository-docs/index.md) の項目から設計・規約と変更対象の正本を確認する。変更による具体的な失敗を検出できる最小の追加確認を選び、通常はモック・fixture・ローカル単体で確認する。対象リポジトリで定める必須チェックを行い、委譲元エージェントや別役割が成功済みの確認は重複実行しない。

完了条件に影響する失敗は担当内で原因を調べて修正し、失敗した確認と直接影響する確認だけを必要に応じ再実行する。個々の失敗を委譲元エージェントへ逐次差し戻さず、進展のない試行を繰り返さない。根拠なく調査を広げる必要がある場合や担当範囲・権限を超える場合は止めて報告し、付随的な失敗を新たな目標にしない。ユーザーが明示したサービス接続検証は指定範囲で行い、環境が不明なら確認する。外部状態や本番への書き込みは検証指示から推定しない。

## 報告と引継ぎ

結果、判断に影響した試行と結果、変更ファイル、実行した確認とログの場所、残る問題を簡潔に報告する。コマンド出力をすべて貼らない。経験した再利用可能な知見は [repository-memory](../repository-memory/SKILL.md) に従い本文を作成する。保存先の所有権がある場合だけ記録し、委譲元が差分で最終採否を決める。
