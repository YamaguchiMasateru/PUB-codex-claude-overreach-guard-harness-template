# リポジトリ経験知

対象は、次の判断や行動を変える、観測・検証に裏付けられたリポジトリ共有の成功・失敗・制約。一度の経験でも再利用性または影響が大きければ候補にする。通常の完了報告、生ログ、重複、再利用できない一時事象は記録しない。個人ローカルメモリーも対象外。

## 委譲元の判断と割当

作業中に再利用可能な失敗・ユーザーの訂正・検証結果を得たときや子から候補報告を受けたときは、明示の呼出しがなくてもこの手順を適用して候補を評価する。すべてのエラーを記録する必要はない。

候補の評価・追加・更新前にこのスキルを読む。関連作業では [索引](../../../.repository-state/memory/index.md) → [短い要約](../../../.repository-state/memory/MEMORY.md) → 必要な項目の順で読み、関係する既存知見を子に渡す。子の報告を観測根拠と照合し、タスク完了前に候補ごと `採用・既存対応済み・不採用・保留` を判断する。既存対応済みは同じ条件・原因・教訓を記録した具体的なメモリー項目で確認し、文書に手順があるだけでは対応済みとしない。不採用・保留は理由を報告し、保留は本文案・根拠も保持して共有メモリーへ保存しない。候補がなければメモリーを更新しない。読取り専用・保存禁止の依頼や、明示の保存依頼を伴わない調査・相談だけの依頼では候補報告に留め、ファイルを変更しない。候補の発見は編集や追加調査の許可にならない。

採用時は既存項目への統合を優先し、新テーマは `.repository-state/memory/lessons/<topic>.md` に1テーマ1件で保存する。成功と失敗を同じテーマで統合し、条件と限界を残す。索引と必要な要約も含め、同時に同じファイルを編集しない所有権を割り当てる。明示依頼なしに過去の記録を一括移行しない。必須規約・正式手順の正本は `.repository-docs/` とし、経験知には適用条件・根拠と `.repository-docs/` へのリンクを置く。利用時や環境変更時に見直し、古い知見には失効・後継を明記する。自動削除しない。

保存先を実装担当に明示して所有させた場合、担当者は作業から記録まで同じ文脈で行い、委譲元は差分を見て最終採否を決める。保存先が未確定なら実装担当は完成本文と根拠を報告し、委譲元が採否・パスを決めて同じ担当者を優先して再利用する。読取り専用の調査・レビューとログのみの検証は完成本文と根拠まで報告する。採用して保存を委譲するときは、本文原文・根拠・関連既存記録・変更範囲を実装担当へそのまま渡し、短い要約から本文を再生成させない。保存だけの follow-up から候補生成や追加委譲を再帰的に始めない。

事前に保存を許可された候補を委譲元が不採用または保留にした場合は、担当者自身による候補記録関連の差分だけ撤回させる。撤回対象は該当本文・索引・要約・候補記録であり、本体作業の差分は保持する。他者の編集は戻さない。委譲元は採用した候補の保存先と所有者を割り当て、保存本文、索引、必要な要約の実在と差分を確認して完了とする。通常の編集作業で保存先を未割当のままにしたことを理由に採用候補を放置せず、未処理候補を残してタスクを完了しない。

## 経験した担当者の本文作成

本文を書くときにこのスキルを読む。観測事実と仮説を分け、成功を無条件の最善策とせず、未確認を確定しない。既存項目を確認し、`本文付き候補・既存対応済み・該当なし` のいずれかを報告する。候補が未確定なら保留理由も報告する。担当に保存先の所有権が明示されている場合だけ保存できる。調査・レビューは読取り専用、検証はGit管理外ログだけに書く。子は委譲元向けの起動評価や採否判断を行わない。

短い記録本文の型（該当しない情報は `未設定`、未確認は理由付きで記す）:

```markdown
# テーマ

- 適用条件:
- 観測結果（成功・失敗を区別）:
- 教訓と次の行動:
- 根拠（確認できるパス・コマンド・資料）:
- 限界・未確認:
- 確認日: YYYY-MM-DD
```
