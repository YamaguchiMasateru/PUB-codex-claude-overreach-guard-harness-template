# Claude Code の読み取り専用役割に残る書込み経路

- 適用条件: Claude Code のサブエージェントで、読み取り専用を `disallowedTools`（`Write`、`Edit`、`NotebookEdit`、`Agent`）の拒否リストで実現している場合。
- 観測結果（成功・失敗を区別）: 2026-10-18 の `investigate` 起動で、`Write`、`Edit`、`NotebookEdit`、`Agent` は公開されなかった（成功）。一方、`Bash`、`Artifact`（publish の `edits` はローカルファイルにも保存される）、MCP の書込み系ツール、`ArtifactData`、`ArtifactComments`、`EnterWorktree`、`Monitor`、`SendMessage` などが公開されており、読み取り専用は方針でのみ守られていた（制限不足）。実際の書込みは試していない。
- 教訓と次の行動: 拒否リストは継承したツールから指定分を外すだけで、MCP や新しい組込みツールは残る。設定で担保するなら `tools` の許可リストにする（MCP は自動的に外れ、今後追加されるツールも入らない）。ただし `Bash` を外すと `inspect_repo.py` や `git diff` が使えず、手順の書き換えと親からの差分の受け渡しが要る。`Bash` を残すなら PreToolUse Hook（frontmatter の `hooks`、または settings の Hook で `agent_type` により判定）で補うが、文字列判定なのでインタプリタ経由で回避されうる。sandbox、permissions、`permissionMode` は役割別の制限にならない（親が `auto`・`acceptEdits`・`bypassPermissions` のとき `permissionMode` は無視される）。起動後は実際に公開されたツール一覧を確認する。このテンプレートでは現状と限界を定義ファイルのコメントと README に残し、環境に応じた変更を促している。
- 根拠: [定義ファイル](../../../.claude/agents/investigate.md)、[README](../../../README.md)（Claude Code の手順と役割）、[起動手順](../../../.agents/skills/delegate-investigate/references/launch-claude.md)。公式: https://code.claude.com/docs/en/sub-agents.md、https://code.claude.com/docs/en/permissions.md、https://code.claude.com/docs/en/sandboxing.md、https://code.claude.com/docs/en/permission-modes.md、https://code.claude.com/docs/en/artifacts.md。
- 限界・未確認: `ask` の実機挙動と、日本語の文字化けが他 OS・既存 Hook の `systemMessage` / `additionalContext` でも起きるかは未確認。各経路で実際に書けるかは未試行（`Artifact` の `edits` が `disallowedTools: Edit` の下で許可確認を経るかなど）。公開されるツールはログイン状態、接続コネクター、CLI のバージョンで変わる。許可リストにしたとき報告手段（`SubagentHandback`）が残るか、`Grep` と `Glob` がない環境で起動できるかも未確認。
- 補完の結果（2026-10-19）: `Bash` は PreToolUse Hook の**許可リスト**で補った（[pretool_guard.py](../../../.claude/hooks/pretool_guard.py)）。実機（claude.exe 2.1.301、Windows、`claude -p`）で、PreToolUse の入力にサブエージェント内だけ `agent_type` と `agent_id` が付くこと、`permissionDecision: deny` を exit 0 で返すと書込みが止まり読み取りは通ることを確認した（成功）。独立 verify の回避探索では、完全一致の拒否が長オプションの一意な接頭辞（`git grep --open-files-i=...`、`sort --out f`、`sort --compress-program=sh`）をすり抜けた。`uv run` を `endswith` で判定すると `--project /evil` や別ディレクトリのスクリプトが通った。`cat .env`（`Read` の deny は Bash に効かない）と `tail -f` も通った。いずれも修正後に拒否を確認した（失敗→修正）。日本語の拒否理由は Windows で文字化けして表示された。
- 補完の教訓: 危険な長オプションは完全一致でなく接頭辞（2 文字以上）で拒否し、`sort`・`git grep` のように危険オプションを持つコマンドは安全なオプションの完全一致の許可リストにして、リスト外の `-` 始まりを全拒否にする。`uv run` は既知の形を厳密に照合し、`--project` とスクリプトは Hook 自身から算出したリポジトリルートに限る。機密ファイル名は全引数で拒否する（網羅ではない）。read-only 判定中の例外は fail closed、規則ファイルや入力の不備は fail open にする。拒否理由は英数字で書く。実装後は別の検証者が実コマンドで回避を探す。MCP の書込み系、matcher 外のツール、`git log -p` などの設定依存の外部実行は残る。
