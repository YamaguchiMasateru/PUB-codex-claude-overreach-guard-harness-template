# 経験知候補の報告だけで保存完了としない

公開用サンプル（ハーネス開発例）。

- 適用条件: 委譲先が再利用可能な知見候補を報告し、親が採否・保存を担当する作業。
- 観測結果（成功・失敗を区別）: ハーネス開発では repository-memory が読まれ、委譲先が候補本文と根拠を報告した。委譲先は保存不可という担当範囲を守ったが、親が採否を明示せず、保存所有者の割当・本文と索引の保存確認を行わないまま終了した。運用文書に対処があることを共有メモリーで対応済みと混同した。Skill の未読や候補の報告漏れが原因ではなかった。
- 教訓と次の行動: 候補を受け取った親が、タスク終了前に採用・既存対応済み・不採用・保留を判断する。採用は本文と索引の実在・差分まで確かめ、既存対応済みは同じ条件・原因・教訓を持つメモリー本文で確認する。docsに手順があるだけで経験知の記録済みとは扱わない。読取り専用や保存依頼のない調査のみでは、候補と判断理由の報告までに留める。
- 根拠: [保存手順の正本](../../../.agents/skills/repository-memory/SKILL.md)、[経験知の位置づけ](../../../.repository-docs/operations/repository-knowledge.md)。候補報告の原文記録は同梱しない。
- 限界・未確認: ハーネス開発時の一例。Skill の自動適用は実行 Hook による自動書込みと同じではなく、指示改善だけで将来の処理漏れが完全に防げるとは保証しない。
