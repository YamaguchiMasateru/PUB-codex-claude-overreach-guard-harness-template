# 検討依頼を実装修正の許可へ読み替えない

公開用サンプル（ハーネス開発例）。

- 適用条件: ユーザーが検討・原因確認に範囲を限定し、その後に再現結果を提示した場合。
- 観測結果（成功・失敗を区別）: ハーネス開発では検討に限定された依頼と再現結果を実装許可と取り違え、コード・テスト・設計書を変更し、個人ローカル設定を新規作成した。範囲を超えた変更として指摘を受けた後、検討と実装を分け、明示の修正指示後に変更した。
- 教訓と次の行動: 直前の説明や自分の修正予定の宣言を、ユーザーの許可の代わりにしない。現在の依頼範囲と以前に与えられた許可を確認し、検討のみと指定された間は分析と案の提示までにする。既に修正が許可されている作業で、同じ許可を繰り返し求める必要はない。
- 根拠: [作業分担の入口](../../../AGENTS.md)、[実装の呼出し手順](../../../.agents/skills/delegate-implement/SKILL.md)。会話と変更報告の原文は同梱しない。
- 限界・未確認: ハーネス開発での範囲の取り違えに関する例。「検討」という語が含まれる全依頼を一律に読取り専用とする規則ではない。
- 確認日: 未設定（公開用サンプル。導入先で検証後に記入）
