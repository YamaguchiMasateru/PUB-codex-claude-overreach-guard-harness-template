# 取り下げた方針の古い参照は、パスの一部の名前でも検索する

- 適用条件: 方針や構成を取り下げた後、文書・計画書・タスク一覧・設定から古い参照を取り除くとき。
- 観測結果（成功・失敗を区別）: 失敗の例。`.claude/skills` というパス全体で検索すると、取り下げの説明だけが見つかった。一方、計画書 §4 #19 と tasks.md の `.gitignore` 例外の列挙には、`/.claude/*` を前提にした `skills/` という名前だけの形で古い参照が残っており、パス全体の検索では見つからなかった。独立した verify の確認で見つかった。
- 教訓と次の行動: パス全体に加えて、親ディレクトリを省いた名前（例: `skills/`）や設定キー名（例: `shared_skills`）でも検索し、見つかった箇所を実ファイル（`.gitignore` など）と照らし合わせる。完了表示（チェックリスト）が実態と合っているかも確認する。名前だけの検索は誤検出が増えるため、結果は目で確認する。
- 根拠: 取り下げ前後の確認は独立した verify の報告による。修正済みの箇所は ハーネス開発元の計画書 `add-claude-harness-plan/codex-claude-mapping.md` の §4 #19 と `add-claude-harness-plan/tasks.md` のフェーズ 3（いずれも配布物には含まれない）。
